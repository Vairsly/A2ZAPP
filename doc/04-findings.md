# 风险、维护建议与待核查边界

返回：[文档入口](./README.md)

以下是静态源码分析发现，未执行线上接口或真机复现。“明确行为”指可直接从实现确认；“风险”说明该行为在特定场景的后果，不代表已在生产环境发生。本次未修改这些实现。

## 1. 建议优先处理

### 1.1 请求日志包含 Authorization

**明确行为：** `httpRequest()` 执行 `console.log('[headers] ...')` 输出完整 headers，业务请求的 Bearer token 会进入日志。

**影响：** 能访问调试日志或采集日志的主体可能获得有效凭据。该行为与文件中“移除敏感信息打印”的注释不一致。

**建议：** 生产环境移除该日志，调试时仅输出脱敏信息。验证时使用虚拟 token 确认日志中不含凭据。

源码：[common/http.js](../common/http.js)，49；请求头注入：[common/request.js](../common/request.js)，32。

### 1.2 记住密码直接保存原始密码

**明确行为：** 登录成功且勾选记住密码后，把 `this.password` 直接写入 `rememberedPassword`，下次加载直接回填。RSA 加密只用于登录传输，不能保护这份本地保存值。

**影响：** 普通应用存储中的密码具有额外暴露面；`clearSession()` 也不会删除此值。

**建议：** 优先使用系统安全存储或基于刷新凭证的登录体验；产品确需记住原始密码时，应定义存储保护和清理策略。

源码：[登录页](../pages/login/login.vue)，112、202；[common/session.js](../common/session.js)，188。

### 1.3 切换无人机保留已有检查内容

**明确行为：** 从检查页进入选择页时带 `from=check`；选择确认只写新 ID/alias 并返回，不写新建标记。检查页 `onShow` 更新无人机后，若没有模式标记直接返回，不清理或切换 `steps`。

**影响：** 为无人机 A 填写的结果、备注和照片可能在选择 B 后提交到 B。离开检查页时的自动保存还可能先为 A 留下一份快照。

**建议：** 将“切换无人机”定义为独立业务动作：保存当前无人机草稿，再明确恢复目标无人机草稿或重置流程；如允许迁移，需在交互上明确告知。

源码：[选择页](../pages/preflightSelectDrone/preflightSelectDrone.vue)，265；[检查页](../pages/check/check.vue)，557、734。

### 1.4 草稿与选择信息缺少账号和环境隔离

**明确行为：** 草稿以 `preflightDrafts[droneId]` 保存，选择信息也是全局存储键；`clearSession()` 只清 token、loginTime、userInfo。

**影响：** 同设备切换账号，或更换客户端服务环境后，仍可能看到或恢复旧上下文的草稿/无人机选择。当前恢复草稿路径没有再次核对该无人机是否属于当前账号；后端是否拒绝提交未知。

**建议：** 使用账号 ID、服务环境、无人机 ID 组合命名空间，并明确退出与账号切换时的本地业务数据策略。

源码：[common/session.js](../common/session.js)，188；[检查页](../pages/check/check.vue)，822、846、897；[历史页](../pages/preflightHistory/preflightHistory.vue)，222。

### 1.5 退出接口网络失败时本地 token 可能残留

**明确行为：** `logout()` 在 `await httpRequest()` 之后才调用 `clearSession()`；若网络请求 reject，该清理不会执行。设置页捕获并忽略错误，仍提示退出成功并跳转登录。

**影响：** 登录页与本地登录态可能不一致；后续 App `onShow` 看到 token 齐全时可能再次进入已登录流程。

**建议：** 本地清理放入确定执行的路径，例如 `finally`；远程撤销失败应与本地退出状态分别处理。

源码：[common/session.js](../common/session.js)，467；[设置页](../pages/settings/settings.vue)，138；[App.vue](../App.vue)，38。

## 2. 业务一致性和错误反馈

| 发现 | 明确行为与风险 | 建议 / 源码定位 |
| --- | --- | --- |
| 放弃草稿不清除已有快照 | 离开弹窗的放弃分支只设置 `discardingDraft=true`。每 3 秒自动保存可能已经生成草稿，放弃后仍可能在历史页显示 | 明确放弃含义；若指删除当前草稿，则删除对应持久化快照。[检查页](../pages/check/check.vue)：712、879 |
| 批次图片上传失败静默处理 | 本批 URL 只在所有上传成功后合并到步骤；后续文件失败时，先前已上传文件的 URL 未写入步骤，外层 `catch` 无提示 | 保留已成功 URL，提示失败项并支持重试；核对无引用文件清理策略。[检查页](../pages/check/check.vue)：1199 |
| 最终提交缺少必拍照片复核 | 步骤和进入汇总时有照片校验；`doSubmitPreflight()` 只检查完成度、无人机和提交锁，未统一复核照片 | 在最终提交入口重用完整校验，后端也必须校验。属于防御缺口，尚未确认正常 UI 路径能否触发缺照片提交。[检查页](../pages/check/check.vue)：929、981、1247 |
| 空状态导航使用 Tab 页的错误 API | 检查页无无人机且无进度时调用 `safeNavigateTo(PAGES.preflightHistory)`，但历史页已注册为 Tab；失败被忽略 | 使用 `safeSwitchTab` 并核对异常入口。[检查页](../pages/check/check.vue)：570；[pages.json](../pages.json) |
| 认证响应解包规则不统一 | `request.js` 接受业务 code 200/201/0，`session.js` 仅接受 200，且均要求 code 与 data 同时存在才走包装解包 | 依据真实接口契约统一解包与 token 字段校验。[common/request.js](../common/request.js)：14；[common/session.js](../common/session.js)：412 |
| 鉴权与上传错误分支不一致 | JSON 请求和上传各维护一套刷新/401处理；上传预刷新失败被忽略后仍尝试上传，JSON 预刷新失败则清会话 | 明确离线、超时、token 撤销和刷新服务错误的处理，并验证两条链路。[common/request.js](../common/request.js)：69；[检查页](../pages/check/check.vue)：1023 |
| 页面错误反馈不足 | 历史 `loadMore()` 无页面级 catch；详情加载失败只显示 `-`；删除记录失败未在页面捕获 | 为网络失败、空数据、鉴权失败分别显示可理解状态，并允许重试。[历史页](../pages/preflightHistory/preflightHistory.vue)：249；[详情页](../pages/preflightHistoryDetail/preflightHistoryDetail.vue)：160、224 |
| 异步列表刷新存在竞争风险 | `reload()` 先清列表/重置页码再调用 `loadMore()`，若旧请求仍在进行，加载锁可能让新请求退出；旧响应仍会追加 | 用请求序号、取消旧请求或状态隔离保证筛选与刷新一致性。[历史页](../pages/preflightHistory/preflightHistory.vue)：150、249 |
| 去重键未包含身份上下文 | `http.js` 去重键不含 Authorization 或 lang，短时间内相同请求可能跨语言或身份复用 Promise | 把影响响应的上下文纳入去重键，或在会话切换时隔离进行中请求。[common/http.js](../common/http.js)：53 |

## 3. 可维护性建议

1. **提取检查模板与模型。** `steps`、`stepMetas` 和详情页元数据存在重复维护；先统一 key、顺序、文案和照片规则，再决定是否接入现有模板接口。当前草稿虽带 `v:1`，恢复逻辑未根据版本执行迁移。
2. **拆分检查页职责。** 将草稿仓储、图片压缩、上传请求和检查校验提取到独立模块，让页面专注交互。上传认证可复用统一策略，但需保留 multipart 的平台差异。
3. **统一环境配置。** 当前默认地址靠源码常量选择，本地代理靠环境变量选择；应提供可追溯的构建环境配置，避免误认为写入 `apiBaseUrl` 存储键即可切换。
4. **清理未接入内容。** `buildMockHistory()`、`buildMockDrones()`、`mockDrones`、未使用接口/存储键属于当前未接入内容；`mockUpload=false` 则仍是可切换的上传测试分支。清理前先核对团队是否用于调试。
5. **补齐可复现工程信息。** 明确 HBuilderX/uni-app 版本、依赖版本和实际构建流程；当前缺少依赖清单，不能把配置存在等同于任何开发环境都能直接构建。

## 4. 后续验证清单

这些是建议进行的验证，不是本次已经执行的结果。

| 场景 | 重点观察 |
| --- | --- |
| 多个并行业务请求同时临近过期 | refreshPromise 是否合并刷新；重放是否携带新 token |
| HTTP 401、业务 code=401、刷新超时、刷新 5xx | 是否错误退出、重复刷新、重复弹窗或遗留登录态 |
| 退出接口断网 | 本地 token 是否清理，回到前台是否再次进入首页 |
| A 无人机填写后切换 B | 步骤、照片、草稿与提交 drone_id 是否一致 |
| 同机切换不同账号或环境 | 历史草稿与选择信息是否泄漏或串用 |
| 自动保存后选择放弃 | 历史页是否仍显示快照，交互是否符合产品定义 |
| 一批多张照片中途失败 | 成功照片是否保留、失败是否提示、服务端是否有无引用文件 |
| 大图、压缩失败、相机取消、拍照返回 | 1600 px/500 KiB 目标、锁状态、临时文件和自动保存是否正常 |
| 有不通过项但全部填完 | 是否允许记录提交，后端 passed 规则是否符合业务 |
| 下拉刷新时旧分页请求未结束 | 是否出现重复、旧筛选数据回流或空列表 |
| Android 实体返回、系统侧滑、多次快速点击 | 离开确认和导航锁是否正常，是否产生重复弹窗 |
| 删除记录、恢复草稿、图片预览 | 后端对象权限是否校验；图片 URL 是否允许正确用户访问 |

后端软删除语义、图片清理策略、字段类型、对象权限、幂等保障及数据库模型均不能由当前前端目录单独确认，需结合后端代码或接口契约补充。
